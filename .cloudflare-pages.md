# Cloudflare Pages — deployment settings

Everything here is entered once in the Cloudflare dashboard. Nothing in this
file is read by any tool; it exists so the settings are recorded somewhere other
than one person's memory.

## Build configuration

| Field | Value |
| :--- | :--- |
| Framework preset | Astro |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | *(leave empty)* |
| Node version | `24` — set as env var `NODE_VERSION` |

## Branches

| Branch | Gets | Indexed by search engines |
| :--- | :--- | :--- |
| `main` | `swiftsecured.com` | Yes |
| `staging` | `staging.swiftsecured.com` | **No** |
| any other branch | `<branch>.<project>.pages.dev` | **No** |

Set `main` as the production branch under **Settings → Builds → Production
branch**. Everything else is automatically a preview.

## Environment variables

Set these under **Settings → Variables and Secrets**, for **both** Production
and Preview unless noted.

| Name | Value | Notes |
| :--- | :--- | :--- |
| `NODE_VERSION` | `24` | Matches local development |
| `SITE` | `https://swiftsecured.com` | Production only. Astro uses it for canonical URLs |
| `PUBLIC_CONTACT_EMAIL` | the real inbox | Without it the apply form tells applicants it failed |
| `PUBLIC_FORM_ENDPOINT` | form-to-email endpoint | Optional; the contact address alone makes the page usable |

`CF_PAGES_BRANCH` is set by Cloudflare itself. Do not add it manually.

## How previews are kept out of the search index

Two independent layers, because one of them silently failing is exactly the kind
of thing nobody notices until the duplicate pages are already indexed:

1. `src/layouts/Layout.astro` emits `<meta name="robots" content="noindex,
   follow">` on every page of any build where `CF_PAGES_BRANCH` is set to
   anything other than `main`.
2. `src/pages/robots.txt.ts` serves `Disallow: /` on those same builds.

Canonical URLs keep pointing at `swiftsecured.com` even on a preview, so a
crawler that ignores both still learns where the real page is.

Verified by building with `CF_PAGES_BRANCH=staging`: all 4,428 pages carried the
noindex tag and robots.txt switched to `Disallow: /`. A build without the
variable produced neither.

## What is NOT on Cloudflare

`swiftsecure.serveousercontent.com` is the homelab preview tunnel, reserved by
the server's SSH key. Unrelated to this, and not to be renamed.
